Les forces et faiblesses des types Pokémon

Comprendre l'efficacité des types

Chaque attaque de type a un multiplicateur de dégâts selon le type du Pokémon attaqué :

  • Super efficace (x2) : L'attaque inflige 2x plus de dégâts
  • Pas très efficace (x0.5) : L'attaque inflige la moitié des dégâts
  • Sans effet (x0) : L'attaque n'inflige aucun dégât
  • Neutre (x1) : Pas de modification de dégâts

Vulnérabilités de sécurité classiques (Web)

Qu'est-ce que ce sont ?

Cette section éducative présente des vulnérabilités web classiques à connaître (à des fins pédagogiques uniquement). Ne jamais les exploiter illégalement.

Cross-Site Scripting (XSS)

Faiblesse : Injection de scripts malveillants dans des pages web vues par d'autres utilisateurs.

Impact : Vol de cookies/session, redirection, modification de contenu.

Mitigation : Échapper les entrées utilisateur, CSP (Content Security Policy), valider/sanitiser les données.

Injection SQL (SQLi)

Faiblesse : Requêtes SQL non paramétrées permettant l'injection de code.

Impact : Lecture/modification/suppression de BDD, élévation de privilèges.

Mitigation : Requêtes préparées (Prepared Statements), ORM, validation stricte.

Cross-Site Request Forgery (CSRF)

Faiblesse : Forcer un utilisateur authentifié à exécuter des actions non désirées.

Impact : Transactions non autorisées, changement de mot de passe.

Mitigation : Tokens CSRF, SameSite cookies, vérification d'origine (Origin/Referer).

Clickjacking

Faiblesse : Masquer des éléments UI dans un iframe transparent pour piéger les clics.

Impact : Actions involontaires sur des sites authentifiés.

Mitigation : En-tête X-Frame-Options ou CSP frame-ancestors.

Directory Traversal

Faiblesse : Accès non autorisé à des fichiers via "../" dans les paramètres d'URL.

Impact : Lecture de fichiers sensibles (/etc/passwd, configs), fuite d'informations.

Mitigation : Whitelist des chemins, normalisation, éviter d'inclure des chemins utilisateur.

Security Misconfiguration

Faiblesse : Configurations par défaut, erreurs exposées, permissions excessives.

Impact : Exposition d'informations, accès non autorisé.

Mitigation : Hardening, désactiver debug en prod, principe du moindre privilège.
